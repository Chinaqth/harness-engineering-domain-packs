# Generator–Evaluator 契约

## 范围与关键旅程

关键旅程是：开发者读取项目约定与参考实现，创建普通页面或 Dialog 页面，集中声明路由，先声明
UI 资源再引用，补充中文职责注释，完成构建前结构扫描，最后执行配置的构建并交付分离证据。

## Generator 责任

- 只实施已批准范围。
- 保持或加强验收标准。
- 记录可复现证据和已知限制。
- 持续更新 `acceptance.json` 和 `progress.md`。
- 不评价或评分自己编写的 Domain 制品。
- 保留 CatchElf 既有 `build-profile.json5` 和其他不相关用户修改。

## Evaluator 责任

- 独立于实现声明进行评估。
- 在隔离环境中复现关键用户旅程。
- 检查安全、权限、兼容性、回滚和证据质量。
- 用证据记录 pass、fail 或 blocked 结论。
- 检查 Domain 规则、工作流、Skill 和评估器是否互相一致，并验证版本迁移边界。
- 独立检查 sample 中目录、路由、资源引用、中文注释和构建证据。

## 证据标准

- 来源声明区分 Owner 要求、项目样例、第三方 HMRouter 上游说明和 HarmonyOS 平台来源。
- 结构审查、静态扫描、Domain 校验、编译和运行时必须作为不同证据类别报告。
- 任何未运行或不可用检查必须标记为 `skipped`、`unavailable` 或 `blocked`，不得写成通过。

## 独立性与职责分离

Generator 可以实施并记录验证结果，但不能给出 G2 最终 verdict。Evaluator 必须独立读取 diff、
复现关键确定性检查，并把结论写入单独评估记录。

## 结论权

最终技术评估结论属于独立 Evaluator；策略范围、例外和风险接受仍属于 `platform-harmony` Owner。

## 升级与争议处理

如果规则需要扩展到非 UI 字符串、强制更换路由框架、修改公共 API 或影响其他项目源码，必须停止，
更新 G2 范围指纹并重新获得 Owner 决策。来源冲突时优先保留冲突并按其权威边界处理，不便利性择一。
