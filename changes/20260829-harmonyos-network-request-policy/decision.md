# HarmonyOS 网络请求开发策略决策

- Status: approved
- Date: 2026-08-29
- Decision owners: `platform-harmony`（用户明确要求按分析方案改造并完成发布同步）

## 决策

采用“Rule 为规范源、Workflow 和现有 Skill 执行、Evaluator 验证”的闭环，不新增独立网络 Skill。
网络工具选择遵循以下顺序：

1. 验证任务指定或当前模块声明的依赖和工具；
2. 不可用时搜索项目内已存在、可解析且符合架构的网络能力；
3. 仍不存在时，在最小业务边界内使用当前 SDK 已验证支持的官方网络接口创建适配层。

保留 Drill UGC 样例的 endpoint、repository、service、transport 和类型化模型分工；不复制
`common_app`、`httpCall`、认证、路由、Toast、响应协议、服务地址或其他项目专属实现。

## 版本决策

新增规则会令一部分先前符合 3.0.0 的网络实现不再符合要求，因此升级为 `4.0.0`。项目可以继续
固定 3.x；迁移到 4.0.0 时只处理新建或实质修改的网络请求表面及其直接依赖链，不要求一次性重写
全部遗留网络栈。

## 重新审视条件

- HarmonyOS 官方网络接口发生版本或弃用变化。
- 多个业务模块需要将局部适配层提升为共享基础设施。
- 组织采纳统一认证、重试、缓存、证书或错误协议。
- 静态依赖解析产生不可接受的误判并存在更可靠的编译器接口。
